## 1. 问题陈述

工程师模式的任务跑在云主机 Claude Code 上，「关掉 App 任务照跑」天然成立，但 App 侧没有「任务」这个概念的投影：

- SSE 流式气泡绑定前台连接，App 退后台/断网后任务进度不可见，`claudeSid` 只解决上下文续接，不解决状态可见性；
- 任务完成、截断（`claude_truncated`）、失败都没有回联——用户只能自己回到聊天页才发现气泡底部有个「继续」按钮；
- 交付授权（`canDeliver`）和截断续跑是两个现成的决策点，但目前都埋在气泡里，没有审批形态。

Muse 最受认可的范式转变是「任务后台跑 + 需要决策才回联」，工程师模式是 PoLang 内与该范式契合度最高、链路最短的场景。

> **评审更正（2026-09-25）**：「关掉 App 任务照跑」在产品语义上成立，但**网关实现上尚未成立**——现状网关 pump 直写 SSE，App 断连即写异常、claude 子进程孤儿化，任务生命周期事实上绑定连接。D4 已将网关解耦升格为硬依赖，见 §4/§7；回联三件套（US-4~6）的实施排在网关改造之后（§8）。

## 2. 方案概述

把工程师任务升格为一等公民：**每次 `POST /v1/claude-chat` 提交即登记一张任务卡**，卡片生命周期独立于 SSE 连接。

三件套：

1. **进度卡**——chat 内任务卡常驻，显示阶段/轮次/成本/耗时；气泡流保留为卡片点开的明细，卡片是任务的锚点。
2. **完成回联**——SSE 断开后任务状态可回拉（服务端新增状态查询接口）；App 后台期间用前台服务/轮询兜底，任务到达终态（完成/截断/失败）时发本地通知。
3. **决策审批卡**——截断续跑与交付授权从气泡底部散点升级为卡片审批态：任务卡在需要决策时切换形态，聚合「将要发生什么」的要素再要授权。

另有**任务中心页**：App 内集中管理入口，聚合进行中和历史任务（见 US-12~16），任务卡是它在 chat 内的投影。

任务卡用**原生 Compose** 实现，不走 ADR-014 的 RICH_HTML 管线（进度实时刷新与一消息一卡的静态 HTML 语义相斥；任务卡是原生组件，ADR-014 的预览卡容器不适用于本场景）。

## 3. 用户故事

**进度态**

- US-1 工程师模式下发送消息后，chat 流顶部（对应该轮）出现任务卡：状态=进行中，展示当前阶段（最近 tool_use 摘要）、轮次、累计成本、已耗时。成本数据源待网关补发（§7：现状网关不发 cost 事件，`ClaudeEvent.Cost` 为死解析路径），补发前卡片降级为不显示成本行。
- US-2 SSE 事件流持续刷新任务卡；气泡明细流行为不变（`ClaudeAgentRenderer` 现有渲染保留），但审批决策点例外——审批态任务的气泡底部「继续」/「交付」按钮隐藏，卡片为唯一入口（见 US-7~9）。
- US-3 点击任务卡展开/收起明细（锚定到对应气泡位置），收起时明细气泡折叠为单行摘要。

**断连与回联**

- US-4 SSE 断开（退后台/断网/进程重建）而任务未达终态时，任务卡显示「后台运行中」；App 回到前台时自动调用状态接口对账，卡片恢复实时态或终态。行为迁移：现状 SSE `onFailure` 直接插入 `chat_inference_error` 错误消息（终态化），任务卡化后该路径改为驱动任务卡进入「后台运行中」，不再插错误气泡。前置：D4 网关解耦落地后「断连任务照跑」才成立，此前本故事降级为「重连即对账、网关回合已死则标记终态」。
- US-5 任务在后台期间到达终态，发本地通知（渠道复用 TAG 扫描通知先例）：标题=任务结果（完成/需继续/失败），点击直达 chat 页并锚定该任务卡。`POST_NOTIFICATIONS` 未授权时降级为仅前台对账（授权请求流程复用 `LlmModelDownloadManager` 先例）。
- US-6 进程重建后任务卡从 Room 恢复：消息提交即插入 TASK_CARD 消息（state=running）并随事件增量更新（对齐 `claude_agent_state` 先例）——而非现状「气泡 done 后才落 Room」，否则进行中进程死亡无从恢复。

**审批态**

- US-7 任务截断（`done.truncated=true` 或 `error.truncated`）时，任务卡切换为审批态：要素=截断原因 + 已用轮次/成本（成本降级同 US-1），动作=「继续」/「到此为止」。「继续」语义与现有气泡按钮一致（同 sid 续跑）；审批态激活时气泡旧按钮隐藏（US-2），迁移期不出现双入口。
- US-8 出现 file_change 且 `canDeliver=true` 时，任务完成后任务卡给出交付审批：要素=分支名 + 改动文件数 + commit 摘要（deliver 返回前以 file_change 计数兜底），动作=「交付 push」/「暂不」。权限门控沿用 `canDeliverClaude` 现状。
- US-9 审批动作结果回填任务卡（已继续/已交付/已放弃），同一任务的同一决策点只审批一次——卡片与气泡状态同源（同一任务状态模型），任一入口操作后另一入口同步失效。

**终态**

- US-10 任务完成：卡片显示结果摘要（末段文本首行 + 轮次/成本/耗时），交付审批按 US-8 挂载。
- US-11 任务失败：卡片显示错误摘要 + 「重试」动作（重发同消息，新任务卡，不覆盖旧卡）。

**任务中心页（集中管理）**

- US-12 入口：Chat 顶栏任务图标（有活动任务时带角标计数）进入任务中心页；任务卡上「查看全部」为次入口。
- US-13 页面分区：「进行中」（含待审批，按开始时间倒序）与「历史」（完成/失败/已放弃，按结束时间倒序，保留最近 50 条）；空态显示引导文案。
- US-14 列表项 = 任务卡同构紧凑形态（标题 + 状态 chip + meta 行 + 进度/结果摘要；审批中项高亮置顶并带动作按钮）。
- US-15 点击列表项回到 chat 并锚定对应任务卡（深链同 US-5 通知点击）。
- US-16 进行中任务在页面内实时刷新（复用任务状态流，不开新通道）。

## 4. 已定决策

- **D1 场景先行**：工程师模式先做，相册域 TaskRegistry（调研 #1）不捆绑；任务卡 UI 组件与任务状态模型按通用形状设计（状态机与渲染分离），但本次只接工程师模式一个数据源。任务状态流宿主为**进程级单例**（AppContainer 域），chat 页/任务中心页/前台 Service 三方消费，不挂 ChatViewModel 内存。
- **D2 原生卡片**：任务卡 = 原生 Compose 组件，新增 `ChatMessageType.TASK_CARD`（或挂 `metadata` 扩展，实现时二选一，倾向独立类型对齐 `HTML_CARD` 先例——ADR-014 计划名 RICH_HTML 未随落地更新，实际枚举名为 `HTML_CARD`）；不依赖 ADR-014 实现排期。注意 `ChatMessageType` 是双端 SSOT，新增枚举会进入 iOS 面——iOS 侧须同步 default 兜底渲染（纯文本摘要占位），完整实现另走 /ios-follow（见 §6）。实证更正（2026-09-25 实现期）：iOS chat 用独立 Swift `MessageType` 枚举、不消费 shared `ChatMessageType`（`iosApp/PoLang/Features/Chat/ChatMessage.swift:50-55`），新增 TASK_CARD 无枚举面泄漏；iOS 接入时点以 chat.yaml 登记为准。
- **D3 回联通道 = 本地通知 + 前台对账，不做服务端推送**：FCM/厂商推送不在本期；后台期间由前台 Service 短间隔轮询兜底（对齐网关 `CT_PHASE_TIMEOUT=300s` 量级——任务分钟级终态，WorkManager 15 分钟最小周期对回联基本无效，仅作进程死亡后的兜底）；前台恢复时即时对账。
- **D4 状态权威在服务端**：App 侧任务是投影；服务端（网关反代 claude-tunnel）新增 `GET /v1/claude-task/status?sid=` 返回 `{state, turns, costCents, summary, updatedAt}`（sid 不存在 → unknown），SSE 仍是实时通道，状态接口是对账通道。**硬依赖（评审升格）——网关三项改造先行**：①回合执行与 SSE 断连解耦（事件写缓冲、断连后回合继续跑；现状 pump 直写 SSE，断连即子进程孤儿化）；②per-sid 状态登记落盘（对齐 `.claude_session` 文件先例，防网关重启丢状态；现状 `SSE_HUB` 回合结束即删）；③sid↔owner 归属校验（Ktor 反代注入 owner 标识、网关登记映射，跨账号查询 → 403；现状 Ktor 纯透传无映射，不解则为越权读取面）。
- **D5 审批外置语义沿用**：审批动作在卡片原生 UI（App UI 层），不在对话流文本内——与 Muse Sentinel 设计同构，延续 Tier A 思路。
- **D6 单任务**：工程师模式同一会话同一时刻一个活动任务；新消息提交即新卡，旧卡进终态或显式放弃（不支持并行多任务编排）。**enforcement**：App 门控（活动任务未终态时新提交需显式确认放弃旧任务）+ 网关 409（sid 已有活跃回合时拒绝新提交——现状 `SSE_HUB[sid]` 覆盖式注册，不拦会同 workdir 并发两个 claude 进程，git 冲突）。「显式放弃」语义 = 本地标记终态、云端回合自然跑完不再回联，非网关侧取消（取消不在本期）。
- **D7 任务中心只做只读管理 + 审批动作**：页面聚合展示与审批操作（继续/交付/重试），不做任务编辑/删除（历史由 Room 自然留存，清理另议）；数据源与 chat 任务卡同属一个任务状态模型（D1 的通用形状在此兑现第一个复用方）。

## 5. 测试决策

接缝（优先复用既有）：

- **状态机纯逻辑**：`EngineerTaskReducer`（事件流 + 状态对账 → 任务卡状态），入 `shared commonMain` 或 androidApp 纯 Kotlin 层，JVM 单测覆盖全状态迁移（US-1/4/7/8/10/11 的分支矩阵）。对齐 `ClaudeSseParser` 纯逻辑单测先例。
- **SSE 解析**：新事件类型（若状态接口需要增量事件）入 `ClaudeSseParser` 既有测试。
- **服务端路由**：`GET /v1/claude-task/status` 用既有 route test 模式（对齐 `ClaudeChatRouteTest`），覆盖鉴权 401 / 限流 429 / **跨账号查 sid → 403**（D4 归属校验）/ 网关联线成败 / sid 不存在 → unknown。
- **网关 Python**：状态登记 / 断连后回合续跑 / 终态查询 / sid 已有活跃回合 → 409，用 `test_server.py` 既有模式（网关是 D4 硬依赖，测试决策必须覆盖）。
- **UI**：ui-driver 截图验证任务卡三态（进度/审批/完成）+ 通知点击深链；screenshot-diff 基线新增任务卡帧。

「完成」= 上述五层测试全绿 + US-1~16 逐条可演示。

## 6. 明确不做

- 相册域 TaskRegistry 统一落地（仅保持组件通用形状，另立 spec 时再抽象）；
- 服务端推送通道（FCM/厂商）、跨设备任务状态同步；
- iOS 端完整实现（工程师模式当前 Android 独占，后续走 `/ios-follow` 另行评估）；但 `ChatMessageType` 是双端 SSOT，新增 `TASK_CARD` 会进入 iOS 枚举面——iOS 侧需同步 default 兜底渲染（纯文本摘要占位），防未知类型渲染异常；
- 并行多任务、任务排队/取消（取消语义需网关侧支持，本期不碰；「显式放弃」仅为本地标记，见 D6）；
- 任务中心的历史清理、搜索、筛选（MVP 只读 + 审批动作，见 D7）；
- RICH_HTML 化任务卡（见 §2 与 ADR-014 D2 的边界说明）。

## 7. 补充说明

- 服务端改造是本期唯一硬依赖，且实际范围大于「新增一个查询接口」（评审实证）：①回合执行与 SSE 断连解耦——现状网关 pump 直写 SSE，App 断连即写异常、claude 子进程孤儿化，任务生命周期事实上绑定连接；②per-sid 状态登记落盘（现状 `SSE_HUB` 回合结束即删，网关重启丢全部状态）；③sid↔owner 归属校验（现状 Ktor 纯透传、无映射，不解会有越权读取）。三项不落地，`/v1/claude-task/status` 只会回答「无活跃任务」。
- 成本字段更正（评审实证）：网关 `translate_stream_line()` 当前**不发** cost 事件，App 侧 `ClaudeEvent.Cost` 是死解析路径（仅日志）——「累计成本」暂无可复用数据源。待办：网关补发 cost（`result.total_cost_usd` → cents；GLM 后端是否填充该字段需首日验证）；补发前 US-1/7/10 降级为不显示成本行。轮次可用（`done.num_turns`）。
- 其他实证备注：`ClaudeChatClient` 未显式关闭 `retryOnConnectionFailure`，建连阶段静默重发 POST 可能造成双回合双卡，实现时显式关闭。
- 设计稿：任务卡组件帧（进度态/审批态/完成态/失败态）随本 spec 同批出 Ardot 稿，token 绑定走既有 sync 通道。
- 关联 spec：`2026-09-25-intent-routing-contract-design.md`（意图路由契约）——工程师模式走独立 `/v1/claude-chat` 链路，TASK_CARD 不经意图路由器；未来相册域 TaskRegistry（Muse 调研 #1）若接入 chat 路由，再在契约表登记对应 UiArtifact。

## 8. 实施分期（评审新增）

| 期 | 范围 | 前置 |
|---|---|---|
| **P1 在场态** | US-1~3、US-7~11（进度卡/审批卡/终态，SSE 在场全功能） | 无网关依赖，可立即开工 |
| **P2 网关改造** | D4 三项：回合与 SSE 解耦、per-sid 状态落盘、sid↔owner 校验；补发 cost；单任务 409 | 单独排期（服务端专项） |
| **P3 回联 + 任务中心** | US-4~6（断连对账/本地通知/进程重建恢复）+ US-12~16 任务中心页 | P2 落地后启动 |

P1/P2 可并行；任务中心页（US-12~16）数据源只读，若需要可提前到 P1 顺车做只读形态，审批动作随 P1 审批态一并验收。
