## 1. 问题陈述

工程侧已把「任务」做成一等公民（`feat/task-center` 已合 main：任务中心双 Tab、`UserTask` 协议 M1、工程师任务卡），但产品文档层零跟进：

- `PRODUCT.md` v3.0（2026-09-18，早于全部任务工作）**「任务」零提及**——产品形态分层无任务位置、路线图五条线无任务线、定位句无任务范式；
- `FEATURES.md` 任务中心页无产品条目（任务卡仅在 §2.7 工程师模式下有一小节）、§1.6 相册管理纯「屏幕+操作」视角。

Muse 调研指出的差距「任务不是一等公民」在工程侧已修复，在产品定位层仍是空白。本 spec 把「任务」升格为显性产品概念，重塑定位与产品文档。

## 2. 已定决策

- **D1 进核心定位句**：任务范式写入一句话定位（不是仅正文补登）。
- **D2 范式链式措辞**：原句「Chat 式相册管理与搜索 + 图片后处理智能编辑」（2026-08-16 定）升格为「**对话式相册管理（自然语言委托 → 后台任务执行 → 完成回联）+ 图片后处理智能编辑**」——保留「管理+编辑」双支柱结构，管理支柱内部升维为委托-执行-回联闭环。
- **D3 路线图新增横切任务线，Muse Top5 全落位**：`PRODUCT.md` §6 新增「任务范式线（横切）」，调研从「非承诺性规划」升格为正式规划；分期 = M1 已落地 + M2/M3 收编 + 回联三件套（依赖 P2 网关）+ 审批三要素卡 + 审计日志 + 周报 feed（依赖 ADR-014）+ 记忆主动化（维持 P2）。
- **D4 历史决策注记不可变**：PRODUCT.md 头部 2026-08-16 等历史决策注记里的旧定位句**保留原句**（决策记录属性）；只更新「现行定位」表述处（§1 当前聚焦、§2.1、§6.1）。新增 2026-09-26 决策注记承载升格。
- **D5 术语 SSOT**：工程师任务 / 用户任务 / 任务中心 的术语边界以 `2026-09-26-user-task-protocol-design.md` §2 为准，产品文档直接采用，不另造定义。
- **D6 差异化叙事**：「隐私版 Agent 任务——同样的后台任务范式，任务数据 100% 不出端」（对照 Muse 云端 VM；ADR-008；Muse Image 三天下架事件为反向验证）。
