## 四、各阶段详述

### 阶段一、规范先行萌芽期（2026-03 ~ 04，272 提交）

零 AI 合著、零工具目录，提交信息自由格式。AI 以聊天问答/片段生成方式参与（无痕迹），但**文档先行的基因已经种下**：AGENTS.md、PRODUCT.md、设计系统指南在立项两天内就位。这一习惯决定了后来所有治理演进的起点高度——后来的一切机制化，都是给已有的文档习惯装牙齿。

### 阶段二、工具化接入期（2026-05 ~ 06，651 提交）

AI 从「动嘴」变成「动手」：质量门禁、开发闭环、截图比对、文档同步检查全部脚本化；Claude Code 与 kimi 先后进场；**Agent First 范式正式立法**（基础设施原子化为 Tools 层，供 AI 编排）。spec/plan 雏形出现。此阶段 AI 仍是辅助位（合著占比 ~10%），但「人操作脚本」已切换为「AI 编排 Tools」。

### 阶段三、Agent First 爆发期（2026-07 ~ 08-15，≈1680 提交）

AI 成为代码主要生产者：7 月 Claude 合著占 69%，日均 32 提交。版图同步扩张（server、iOS、工程师模式）。**副作用集中暴露**：文档漂移、过程文档堆积、双端不一致、多工具配置分叉——爆发期制造的问题直接定义了下一阶段的议程。月末 claude-tunnel 破土，埋下自举的种子。

### 阶段四、机制化治理期（2026-08-16 ~ 09，≈720 提交）

从「能用」到「可控」，三条战线同时推进：

1. **模型分工**：K3 写代码 + GLM 审查的跨模型交叉验证（写审不同模型），逻辑档位与物理模型解耦，引入额度经济学
2. **SSOT 泛化**：同一洞察三次应用——文档 SSOT（08-01）→ skills SSOT（08-03）→ 设计 SSOT（tokens + per-screen YAML，08-09/15）；Ardot 钉死为预览层，事实归属 git
3. **管线与门禁**：worktree 隔离强制、沉淀管线立法（单向引用，check_doc_sync 第 5/6 项强制执行）、[PARITY] 成为第六条全局红线、OTA 诞生（09-29）

此阶段还有一个**方法论级别的自我纠错**：「iOS 读 Android 源码翻译」路线被证伪，改为 spec → tokens → 双端各自实现 → 截图比对闭环，并把纠错结论固化为 skill 强制约束（ui-parity-guard）。

### 阶段五、自举飞轮稳态期（2026-10 ~，≈320 提交）

标准回路固化并高频运转：**spec → worktree 分支 → 实现 → 三端验证 → 当日沉淀 → --no-ff 合 main → OTA 遛狗包**。提交量回落不是减速，而是从堆量转向收口；验证主体从「编译通过」转向「真机日常使用中暴露问题」（10 月大量手势/布局/白卡修复均来自遛狗反馈）。

## 六、四条专项主线

### 1. ui-driver——自动化测试进 loop 研发闭环（07-02 建成）

雏形在清明假期（04-05/06「Kimi 2.5 分层自动化策略」「单实例多角色自愈循环」探索）与 05-10「设备端测试全自动闭环」（auto-dev-loop）；**07-02 ui-driver 建成**（UiDriverClient JSON-RPC over adb + accessibility skill），AI 的验证感官从「截图看图猜」换成「结构化无障碍数据断言」（text/contentDescription/bounds 精确驱动）；**07-28 立法「退役非 ui-driver 测试」**，ui-driver 成为唯一认可的测试路径；08-09 扩展至 iOS（真机无人值守 5 阶段闭环）。**方法论意义**：改代码 → 编译 → 装机 → 驱动 UI → 断言 → 读日志的闭环从此无人值守可跑通——这是 7 月提交量翻三倍的验证侧前提，也是「AI 主导」与「AI 辅助」的分水岭。

### 2. 工程师模式——App 内嵌「能改自己的 AI」（07-31 起）

claude-tunnel（07-31）→ AI 工程师模式成型（08-01：诊断能力合并 + 白名单读写分离 + push/PR/auto 三交付通道）→ 问题上报对接 GitHub issue（08-01）→ 工程师任务卡（09-25）→ 任务中心双 Tab 白名单收敛（10-11）。**方法论意义**：AI 从 IDE 里的工具变成产品内的一等公民，形成第一个不依赖桌面 IDE 的开发回路。

### 3. 遛狗包——反馈回路从数据线到 OTA 分钟级（09-29 起）

adb 单人闭环（05-10 auto-dev-loop）→ OTA 双轨自更新（09-29）→ 后台下载自动安装（10-05）→ debug 免登录/免配额 friction 清零（10-21/22）→ 全月 24 包 + versionCode 递增守卫（10-30）。**方法论意义**：merge 即送达，真机反馈成为迭代的主输入源。

### 4. 设计层工业化——Ardot × 双端一致 × SSOT（08-08 起）

iOS 开线（08-08）→ PARITY 三连立法（08-09）→ /ios-follow 编排（08-10）→ token codegen + Ardot 预览层定位（08-15）→ 快照入库（08-16）→ 商店图收敛设计稿（09-06~08）。ardot 相关提交按月 65→45→10，标志体系从建模期进入维护期。**方法论意义**：多 AI 工具 × 双平台协同时，唯一事实来源 + 机器门禁是防漂移的唯一解。

### 主线合流：自我改进飞轮（阶段五的完整形态）

```
真机遛狗（OTA 分钟级送达，24 包/月）
    ↓ 体验中暴露问题
App 内上报问题（→ GitHub issue）/ 工程师模式对话
    ↓
AI 工程师诊断修复（App 内嵌，白名单读写分离）
    ↓ 交付按钮（push/PR/auto）
合 main → ota-publish.sh 一键发包
    ↓ 回到第一环
```

项目区别于一般「用 AI 写代码」实践的本质特征：不仅用 AI 生产代码，而且**把 AI 生产代码的能力本身做成产品功能**，再用这个功能加速自己的迭代；设计层 SSOT 则是这个飞轮在双端不失真的地基。

## 七、五条演进主线（纵向总结）

1. **AI 角色**：咨询顾问 → 有手脚的执行者 → 主力产出者 → 被治理的劳动力 → 流水线工人
2. **流程**：无流程 → 脚本闭环（05）→ **ui-driver 结构化 UI 测试进闭环（07）** → spec/plan 流（07）→ worktree 隔离（08）→ 沉淀管线 + 门禁（09）→ 全回路机械化（10）
3. **模型策略**：无 → 单模型（Claude）→ 四工具并行 → 双模型交叉分工 + 档位解耦（K3 写 / GLM 审）
4. **文档观**：文档先行习惯 → 三层体系（PRODUCT→FEATURES→AGENTS）→ 活文档/快照/过程文档三分 + 机器可读（`[agent-task]`、结构化提交信息）
5. **SSOT 泛化**：文档（08-01）→ skills（08-03）→ 设计 tokens/specs（08-09/15）——「多消费者协同时唯一事实来源 + 机器门禁」这一洞察的三次应用
