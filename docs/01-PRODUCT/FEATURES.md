## 1. 智能相册与图片编辑（核心产品与默认首页）

### 1.1 产品定位

相册与图片编辑是 PoLang 的**核心产品场景**与**应用默认首页**。用户在这里完成照片浏览、搜索、管理、美颜编辑等高频操作。相机作为内容采集入口，照片拍摄后自动进入相册流程。

**Agent 介入方式**：
- 语音/文字命令调节编辑参数（"磨皮再强一点""帮我调成复古风"）
- 自然语言相册搜索（"找出去年夏天的照片""有哪些合照？"）
- 批量处理（"把这些照片都调成冷色调"）
- AI 一键优化（"帮我优化这张照片"）
- 自然语言相册管理（"把这张照片移到旅游相册""删除模糊的照片"）
- 智能分类查询（"显示所有猫的照片""按地点分组"）

### 1.2 相册首页

相册首页是用户打开 PoLang 后的首屏，核心能力（整理、聊天、人物、回忆）从这里进入（打标已并入整理页 SCAN tab）；相机为全屏路由（仅头像拍摄进入），模型中心入口在相册顶栏最左与设置主菜单（两处）。

**页面布局**
![相册首页布局分区](assets/diagrams/feat-gallery-layout.png)

**底部导航**（悬浮胶囊，纯图标无文字标签，与主页面 Pager 页序 1:1，2026-09-06 导航统一）
- 相册：本页高亮（显式回家路径）
- 整理：整理中心（类目体系 v2 六类目清理 + 去重 2.0）+ 扫描双 Tab（主页面 Pager 页 1，相邻页瞬时切换，左滑即达；打标图标已移除，深链经 organizeTabRequest 预选 SCAN tab）
- 聊天：AI 助手页（沉浸式二级身份：聊天页自身不渲染底 bar）
- 人物：人脸聚类页（根页，人物项高亮）
- 相机已路由化（仅头像拍摄进入，无常驻入口）；模型中心入口在相册顶栏最左与设置主菜单两处
- 模型中心：模型下载/设置入口（必须模型扫描前提醒；推荐模型 Wi-Fi 下默认静默预下载，可在「推荐」Tab 关闭）
  - 模型中心分类页交互：顶部 Chip 风格分类标签栏（可横向滚动），下方分类页支持横滑切换（HorizontalPager），左右滑动或点按标签均可切换
  - 分类含义：「必须」装机必备模型（仅相册打标/人脸/翻译等核心模型，2026-08-19 起不含任何语音模型）/「相册打标」TAG 与语义搜索相关模型 /「美颜相机」相机与美颜相关模型 /「语音」语音相关模型（chat 类实质为语音模型：ASR 语音识别 + KWS 唤醒词，已移至末尾；均归「推荐」，按需下载）
- 主页面（相册/整理/聊天/人物/回忆，5 页）支持全屏横滑跟手切换：拖动实时跟随手指、松手物理吸附，线性顺序无循环回绕；点击底部图标切换为瞬时跳转（无滑动动画）。2026-08-26 起相机自主页面 Pager 移出、改为 NavHost 全屏路由（唯一用户入口为头像拍摄，Agent 指令链路保留），相册整理（去重 2.0）升为 Pager 页 1，详见 `docs/superpowers/specs/2026-08-25-album-dedup-design.md` §11

**分组浏览（顶栏 Sort 下拉菜单）**
- 顶栏「Sort」图标下拉选择分组模式：全部（不分组）/ 日期 / 人脸 / 人物 / 风景 / 位置（`GroupingMenu`，无分类标签 chips）
- 自动分类：AI 识别照片内容生成智能标签（Florence-2 / Qwen3-VL-2B 打标），支撑人脸/人物/风景/位置分组
- 混合视图：默认「全部」不分组时间轴
- 自定义相册：规划中（用户创建命名相册，手动添加/移除照片）

**视图模式**
| 模式 | 说明 |
|------|------|
| 网格视图（默认）| 3 列缩略图，长按进入多选 |
| 时间线视图 | 规划中：按日期分组，大图预览，左滑查看更多 |
| 年视图 | 规划中：年度精选回顾，大图 + 日期标注 |

### 1.3 媒体查看器

**交互**
- 双指缩放（1x~4x）
- 缩放态优先平移，禁用翻页
- 回到 1x 后恢复翻页
- 展开/收起跟随手指轨迹
- 左右滑动切换上一张/下一张
- 上滑删除：全屏大图上滑触发删除（`SwipeUpDeleteGesture`），移入系统回收站；API < 30 无系统回收站时降级为永久删除（走删除授权流）

**工具栏**
- 顶栏：关闭 + 拍摄日期 | 信息 + 更多菜单（图像理解 / OCR / 人脸关键点）
- 底栏：发送（分享）| 编辑 | 证件照 | 删除
- 视频：播放/暂停 | 进度条 | 音量 | 全屏
- 半透明深色背景，浅色图标

**媒体信息浮层**
- 点击「信息」按钮弹出
- 显示：拍摄日期、位置（地图缩略图）、分辨率、文件大小、设备型号
- AI 标签：自动识别的场景/物体/人物标签
- EXIF 原始数据（可展开）

### 1.4 静态图美颜编辑

**入口**
- 工具栏「编辑」按钮（仅图片）
- 长按图片直接进入
- AI 对话触发（"编辑这张照片"）
- 从聊天页图片消息点击「编辑」

**流程**
1. 异步加载原图 + 人脸检测
2. 显示 BeautySelector 面板（同相机）
3. 拖动滑块调节参数，200ms debounce 刷新预览
4. 保存为新文件，不覆盖原图
5. 保存后自动进入对比模式（左右分屏：原图 vs 编辑后）

**AI 编辑能力**
- AI 一键优化：一键应用通用优化预设（P0；场景感知推荐规划中），详见 [1.4.1 AI 一键优化](#141-ai-一键优化)
- 精准局部美颜：左眼/右眼/左脸/右脸独立调节（P0，开发中）
- 对话式调节：通过聊天指令控制美颜参数（P1，开发中）
- 智能消除：圈选物体自动消除，AI 填充（P1，开发中）
- 专业调色面板：曲线、HSL、分区调色（P1，规划中）
- 构图辅助：自动裁剪推荐（三分法、黄金分割），水平校正（P2，规划中）
- AI 增强：去雾、超分辨率、低光增强（P2，规划中）

### 1.4.1 AI 一键优化

> **定位**：P0 核心能力。通过一键触发，系统自动应用推荐的美颜、滤镜、调节参数，让用户无需手动调参即可获得更好的照片效果。
>
> **技术方案（2026-08-06 现状）**：编辑器内走抽卡闭环（`AiOptimizeUseCase.optimizeWithGacha`）——以场景预设为锚点采样 4 候选、512px 渲染、端侧 NIMA 评分 + 退化守卫选优，随后进入「先预览后应用」对比模式（最优卡大图预览，用户点「应用」才生效）。NIMA 模型未下载时退回 `Scene.GENERAL` 通用预设直接应用（`fastOptimize`），无需网络、无需授权。早期版本中的 ML Kit 场景分析已移除。远程 Smart 路径（视觉大模型场景分析 + 推荐，`AiOptimizeUseCase.smartOptimize`）为规划中能力，已预留授权与降级通路（未授权或引擎不可用时自动降级为 Fast 路径）。详见 `docs/03-TECHNICAL-SPECS/AI_OPTIMIZATION.md` §11.5。

#### 场景感知推荐（规划中）

> 以下为规划中能力，当前实现尚未落地。

**推荐卡片**（规划中）：
- 场景图标（根据识别结果动态）：🧑 人像 / 🍜 美食 / 🏔️ 风景 / 🌙 夜景 / 📝 文档 / ✨ 通用
- 场景名称："户外人像" / "美食" / "风景" 等
- 一句话说明："已适度磨皮美白，提亮肤色"
- 操作按钮：「应用」「微调」「换一换」（「换一换」走远程 Smart 路径重新推荐，需授权）

**批量优化**（规划中）：
- 单次最多 50 张
- 仅使用本地 Fast 路径（不使用远程 Smart，避免大量上传）
- 处理在后台线程，用户可离开相册
- 完成后通过本地通知或相册内提示告知用户

#### 隐私与授权

- **本地 Fast 路径**：无需任何授权，敏感数据不出设备
- **远程 Smart 路径**（规划中）：
  - 首次触发时显示授权说明弹窗
  - 设置中提供「允许云端 AI 优化」开关
  - 上传图片压缩至最长边 512px，JPEG 质量 80
  - 云端模型仅用于生成参数，不存储用户图片

| 指令 | Agent 响应 | 执行位置 |
|------|------------|----------|
| 「帮我优化这张照片」 | 发送优化后的图片 + 一句话说明 | 本地/远程生成 → 聊天页返回 |
| 「把这张照片修好看点」 | 同上 | 同上 |
| 「优化后太白了」 | 进入编辑器或重新推荐低美白参数 | 同上 |

**编辑历史**

- 支持撤销/重做（最多 30 步）
- 支持对比原图（长按/按钮）
- 每次保存保留编辑参数副本，可重新调整（非破坏性编辑）

### 1.5 智能分类与搜索

**智能分类**
| 分类维度 | 技术方案 | 说明 |
|----------|----------|------|
| 人脸聚类 | InsightFace（MNN）RetinaFace + Glint360K ArcFace + 人物命名/关系（🔄） | RetinaFace 检测人脸 → Glint360K R100 提取 512 维特征向量 → DBSCAN 聚类分组，"人物"标签；可命名、标记"我"、声明关系（`PersonRepository`） |
| 地点分组 | GPS 信息聚类 | 按拍摄地点聚合，支持地图视图 |
| 场景识别 | Florence-2 端侧打标（`domain/tag/florence2`） | 自动标注风景/美食/建筑/动物/文字截图等，3-Pass 链路（详见 `TAG_GENERATION.md`），中英双字段 + MT 汉化 |
| 日期聚合 | EXIF 日期 | 按年/月/日分层聚合 |

**人物封面选择** ✅ 已落地（`domain/aesthetic/`）
- 人物聚类完成后，由 `AestheticScoreWorker` 在后台对人物名下候选照片打分，`CoverSelector` 自动选出最佳封面写入 `PersonEntity.coverMediaId`
- 评分模型：NIMA 美学分（1-10）+ eDifFIQA 人脸质量分（0-1）加权组合（W_FACE=0.6 / W_AESTHETIC=0.4）
- 端侧推理（NNAPI 加速），模型会话跨调用复用，不消耗远程额度

**自然语言搜索** ✅ 已落地（`ExplicitFirstSearchPipeline` + `QueryParser`，详见 `GALLERY_SEARCH.md`）
- 全能搜索框：位于相册首页顶部，支持混合查询
- 查询示例：
  - "找出去年夏天的照片" → 时间 + 场景过滤
  - "有哪些含食物的照片" → 内容识别过滤
  - "我和小明的合照" → 人脸聚类 + 关键词
  - "在上海拍的照片" → 地点过滤
  - "最近一个月拍的视频" → 类型 + 时间过滤
  - "我女儿的照片" → **人物关系检索（🔄 开发中）**：称谓词表（`KinshipLexicon`）→ 关系图谱（`person_relations`）→ 人脸簇
- 搜索结果显示为可交互媒体网格
- 支持从搜索结果中直接编辑/分享/删除
- 搜索历史保留（本地存储，最多 20 条）

**人物记忆与关系（🔄 开发中，未合并 main）**
- 事实记忆：用户「帮我记住…」声明的事实统一收口于 `MemoryRepository`（`memory_facts` 表），来源含聊天工具与 JS 沙盒写通路
- 人物命名 / "我"标记：为人脸簇命名，全局唯一"我"
- 关系图谱：声明「subject 是我的 predicate」（配偶/子女/父母/兄弟姐妹/祖辈/孙辈/其他亲属），幂等覆盖、级联删除，支持备份导出/恢复

**OCR 文字提取**
- 触发方式：工具栏「提取文字」按钮 / AI 对话触发（"这张图上的文字是什么？"）
- 展示方式：原位浮层（白色卡片 + 黑色遮罩）
- Header：标题 + 字数统计
- Content：可滚动文字，支持选中复制
- Footer：复制全部 / 分享按钮
- 识别语言：自动检测（中文/英文为主），支持手动切换

### 1.6 相册管理

**任务范式（2026-09-26 起，相册管理的第一视角）**
- 相册域的长耗时管理操作——打标扫描、去重扫描、整理清理、模型下载——在产品语义上是「用户委托 Agent 执行的任务」：自然语言或入口发起 → 后台执行 → 任务中心观察与控制（暂停/恢复/取消/重试）→ 完成回联（规划中）
- 任务统一入口为任务中心（§3.6）：已接入可控协议的体系（TAG 扫描、模型下载）以用户任务呈现；去重扫描 / 美学打分 / 人脸重聚类待收编（M2/M3），收编前不进入任务中心
- 本节以下各小节为相册管理能力明细；任务视角的产品定位见 `PRODUCT.md` §2.1 任务层

**自定义相册（规划中）**
- 创建命名相册（支持封面自定义）
- 手动添加/移除照片
- 智能相册：基于规则自动收录（如"最近 30 天拍摄""收藏的照片"）
- 相册排序：支持置顶、拖拽排序

**批量操作**
- 多选模式（长按进入）
- 批量：删除、分享、收藏、移动至相册、应用美颜/滤镜
- 全选/反选
- 选择栏显示选中张数

**存储管理**
- 空间释放统一由整理中心（类目体系 v2）承载：Hub 首页「Estimated reclaimable」外显可释放空间，大文件为六类目之一（大视频 + 超分辨率照片），不再单列"> 10MB 文件列表"扫描页
- 删除统一进系统回收站，30 天内可恢复（API 30+；API ≤ 29 走旧删除授权流）
- 回收站通用编排（`TrashSessionController`）✅ 已落地：统一承载整理中心 / 去重 / 预览页删除的回收站会话；设置提供「MANAGE_MEDIA 静默删除」开关（默认关闭，开启后经系统 MediaStore 授权静默删除，无需逐条系统确认）
- 整理中心（类目体系 v2）✅ 已落地（`domain/organize/` + `features/gallery/organize/` + hub `features/gallery/dedup/DedupHomeHub.kt`；整理+扫描合并页「整理」Tab，主页面 Pager 页 1）
  - 六个互斥清理类目（一张媒体只进一个桶，按优先级裁定）：重复与相似 / 屏幕内容（截图+录屏）/ 文档与票据 / 低质人像 / 低质量照片（真模糊与曝光异常）/ 大文件（大视频 + 超分辨率照片）
  - Hub 首页：「Estimated reclaimable」大数字 = 各类目高置信建议删除的真实并集（重复组自动保留一张，不虚高）；类目卡带置信度徽标（● 高置信 / ○ 需确认 / 受保护数）、预览缩略图，按建议价值排序
  - 三级置信度：高置信（强信号命中，详情页默认勾选）/ 需确认（仅列出）/ 弱信号；全部判定端侧完成，照片不出设备
  - 价值保护：老照片（5 年以上）、稀缺人物照片、收藏或查看过的照片自动标记「可能是珍贵照片」——不默认勾选、不计入可释放数字、详情页单独分区带盾牌角标
  - 信号未就绪的类目显示「需先扫描」引导卡（点击跳扫描 Tab），不再静默消失
  - 类目详情页三段分组（建议删除 / 请确认 / 可能是珍贵照片）+ AI 预选开关；删除进系统回收站，30 天内可撤销
  - 「Quick tidy up」手势快速整理：全屏大图右滑保留 / 左滑跳过 / 上滑删除，废片优先排队（截图 → 模糊低质 → 低质人像 → 其他近期照片），与类目页同一套判定口径
- 相似照片清理（去重 2.0）✅ 已落地（`domain/dedup/` + `features/gallery/dedup/`；为整理中心 hub 的固定「重复与相似照片」展开卡，入口：设置主菜单「相册整理」一级入口 / 相册页悬浮导航整理 tab / 相册页左滑）
  - 三级尺度可选：精确重复（MD5）/ 视觉重复（pHash）/ 相似场景（连拍时间窗）
  - 结果页按级别分 Tab：批量操作（底部 CTA / 全选本类）均为当前 Tab 口径，L3 场景相似不参与批量（需逐组确认）

### 2.7 AI 工程师模式

> 面向开发者/高级用户的调试与代码协作模式，在普通对话能力之上接入云主机 Claude Code。

**入口与链路**
- Chat 输入区「AI Engineer」toggle 开关，开启后当前会话切换为工程师模式
- 消息经自建服务端（`POST /v1/claude-chat`）→ claude-tunnel 隧道 → 云主机 Claude Code 流式执行，SSE 下行实时回显
- 会话标识 `claudeSid` 本地持久化，进程重建后可续接上下文

**气泡交互**
- 工程师回复由 `ClaudeAgentRenderer` + `ClaudeMarkdownSegmenter` 分段渲染
- 长代码块默认折叠，可点击展开/收起
- 输出被截断时（达到轮次上限或阶段超时）气泡底部显示截断标识（`claude_truncated`）+「继续」按钮，点击让 Claude 接着输出

**任务卡（2026-09-25 起，审批唯一入口）**
- 每次工程师模式提交即在对话流插入一张任务卡（TASK_CARD 消息，锚定提交位置）：RUNNING 态实时显示当前阶段、轮次、成本、改动文件数，可展开明细看步骤轨迹
- 审批动作收口到卡片：截断 →「继续 / 到此为止」；有文件改动且账号可交付 →「Push branch / 暂不」；失败 →「重试」（重发原指令，新回合新卡，旧卡保留）；同一决策点只审批一次，结果（已继续/已交付/已放弃/已跳过交付）以 chip 固化在卡片上
- 终态：已完成卡显示结果摘要（末段回复首行）；失败卡显示错误摘要可重试；交付失败保持待审批态可重试
- 气泡的文本/步骤明细展示保留，但审批按钮（继续/交付）与「响应截断」标识一并收口到任务卡——会话内存在任务卡时气泡不再显示截断标识与这两类按钮（legacy 仅供旧会话记录）
- 任务中心（§3.6）聚合全部工程师任务：Chat 顶栏任务图标入口（角标为两类任务进行中合并计数），进行中/历史分区；审批动作页内完成（交付 push / 暂不 / 放弃），继续 / 重试切回对应会话执行

**代码交付权限**
- 代码交付（push / PR / auto）受服务端 AI 工程师白名单限制：接口返回 `{available, canDeliver}`，仅 `canDeliver` 账号可见交付操作
- 只读诊断（查看日志/崩溃/聊天历史/运行时状态/相册摘要）对所有已认证账号开放

### 2.8 上报问题

- 设置页「其他」分组「上报问题」行 → 弹出 `ReportIssueDialog`（2026-09-26 入口自 Chat 顶部栏迁入设置页）
- 表单：分类（崩溃 / Bug / AI 问题 / 其他）+ 标题 + 描述
- 提交至 `POST /v1/report-issue`，服务端脱敏后自动在项目仓库创建 GitHub issue，成功返回 issueId 提示
- 匿名访客（Guest）账号不可上报，对话框内显示引导提示

## 3. Agent 交互

### 3.1 交互模式

PoLang 提供两种交互模式，用户可自由切换：

| 模式 | 入口 | 适用场景 |
|------|------|----------|
| **对话模式** | 底部输入栏（语音按钮默认关闭，见 §3.4） | 复杂指令、连续调节、探索发现 |
| **快捷模式** | 右侧控制栏（相机/编辑页内） | 高频单操作、快速调节 |

> **注（2026-08）**：端侧文本 LLM 已移除。相机/编辑的语音与文字指令均走远程模型 tool_calls（需网络）。端侧保留 VLM 打标、人脸检测、ASR 语音输入等能力。

### 3.2 对话模式

**界面布局**
- 输入栏位于屏幕底部，半透明毛玻璃背景
- 点击展开对话面板，显示历史消息
- 支持文字输入；语音输入（按住说话）为默认关闭的实验能力——2026-09-20 产品定性「无语音输入需求」，VoiceButton 已从设计稿移除，代码中按钮仍由语音模式开关门控（见 §3.4）
- **模型状态显示**：输入框左侧显示当前模式标识，点击可手动覆盖或查看说明

**Agent 反馈规范**
- **确认类**：「已为你调高美颜强度」
- **澄清类**：「你想调节磨皮还是美白？」
- **建议类**：「光线较暗，是否开启夜景模式？」
- **错误类**：「抱歉，我没听懂，请再说一次」
- **模式切换提示**：「当前使用远程模型（DeepSeek）」
**多轮对话示例**
```
用户：调高美颜
Agent：已为你调高美颜强度（磨皮+20）
用户：再高一点
Agent：已将磨皮提升至 50
用户：换一个滤镜
Agent：已切换至「胶片金」滤镜
```

**语音输入模式**

| 模式 | 触发方式 | 适用场景 | 默认状态 |
|------|----------|----------|----------|
| **Push-to-Talk** | 按住麦克风按钮说话 | 精确控制、嘈杂环境 | 默认关闭（语音模式开关默认 DISABLED，开启后出现语音按钮） |
| **WakeWord** | 自动检测语音活动 | 免手操作、快速指令 | 默认关闭，可在设置中开启 |

**语音入口显隐（2026-08-19 起全面默认关闭；2026-09-20 产品定性「无语音输入需求」）**

语音为「默认关闭的实验能力」，VoiceButton 已从设计稿移除，Android 代码保留并由开关门控，iOS 不实现：

| 入口 | 门控开关（位置：设置 → 沙盒与权限 → 语音） | 默认 |
|------|------|------|
| 相机页语音控制悬浮钮（RecordVoiceOver） | 「语音控制入口」开关 | 关（不显示、不启动唤醒词监听） |
| 相机页 AI 对话悬浮钮（KeyboardVoice 图标） | 「相机页 AI 助手入口」开关（2026-08-19 新增） | 关 |
| Chat 页 / Agent 共享面板输入框语音按钮（语音输入态） | 「语音控制」模式 ≠ DISABLED | 关（产品已无需求，代码保留由开关门控；已记忆的语音输入态自动回落文字） |

其他页面（相册等）不再提供悬浮语音/AI 入口。KWS 唤醒模型为可选模型，归「推荐」分类按需下载。

**语音处理流程**
```
AudioRecorder → VAD 检测 → ASR 识别 → LLM 解析 → 命令执行
```

**关键参数**
- VAD 阈值：40dB（平衡灵敏度与误触发）
- 最小语音时长：100ms
- 最大片段时长：4000ms
- 静音超时：800ms

**Agent 语音反馈**
- 识别成功：「已为你调高美颜强度」
- 识别失败：「抱歉，我没听清，请再说一次」
- 命令执行：「正在切换至前置摄像头」
- 端侧能力不足：「这个指令有点复杂，让我想想...」
- 模式切换：「当前使用远程模型（DeepSeek）」

### 3.5 体验红线

- **响应延迟**：Agent 回复首字 < 1.5s（远程推理）
- **语音响应**：ASR 识别到命令执行 < 3s（远程推理）
- **远程模型切换延迟**：< 200ms，无卡顿感
- **反馈完整**：每个用户输入必须有可见反馈，包括降级提示
- **渐进披露**：复杂能力通过对话引导发现，不一次性罗列
- **降级透明**：网络不可用时明确告知用户（可选）
- **对话恢复**：应用重启后对话历史恢复 < 500ms

### 3.6 任务中心（✅ 已落地）

> 任务是一等公民（2026-09-26 产品决策，参照 Meta Muse 调研）：任务中心是「app 正在替我干的事」的统一观察与控制面。术语边界（SSOT：`docs/superpowers/specs/2026-09-26-user-task-protocol-design.md` §2）：**工程师任务** = AI 工程师模式的代码任务（卡片在 chat 消息流，交互见 §2.7）；**用户任务** = 扫描 / 下载 / 整理等 app 级长耗时后台操作；**任务中心** = 统一承载两类任务的页面。

**入口与角标**
- Chat 顶栏任务图标为主入口；任务卡「查看全部」为次入口
- 角标 = 工程师进行中数 + 用户任务进行中数合并计数
- 默认 Tab：工程师有活跃任务 → 工程师任务；否则后台任务；均无 → 工程师任务

**双 Tab 结构**
- 顶部一级 Tab「工程师任务 | 后台任务」（五语）
- 各 Tab 内进行中 / 历史双分区：进行中（含待审批，按开始时间倒序；审批中项高亮置顶并带动作按钮）；历史（完成/失败/已放弃/已取消，按结束时间倒序，封顶 50 条）
- 空态显示引导文案

**用户任务卡（后台任务 Tab）**
- 卡片构成：类型图标 + 标题（体系 displayName 原样展示，或按任务类型取 string resource）+ 状态 chip + 进度条（无法量化时不定进度）+ 进度文本（如「512/2048」「12.3 MB / 45 MB」）+ ETA + 按 `supportedActions` 渲染的动作按钮（暂停/恢复/取消/重试）+ 错误摘要（按 errorCode 取五语资源，体系原文细节追加展示）
- 动词语义：暂停 / 恢复 / 取消 / 重试——能力由体系声明、按状态推导，UI 无业务分支；动作失败不弹 toast（默认反馈 = 状态未变化，以体系状态为准，不乐观更新）
- 点击卡片跳转来源场景：TAG 扫描 → 扫描控制页；模型下载 → 模型中心
- 首批接入：TAG 扫描（整个扫描会话 = 1 个任务）、模型下载（每个模型 = 1 个任务，并发多任务）
- 启动对账：进程死于任务中，重启后任务以「已中断——点重试重新开始」呈现（FAILED + 重试按钮）
- 语义承诺：出现在任务中心的任务都可控；未接入可控协议的体系不出现（去重/美学/重聚类 M2/M3 收编后才进入）

**工程师任务 Tab**
- 列表项为任务卡同构紧凑形态：标题 + 状态 chip + meta 行（轮次/成本/耗时）+ 进度/结果摘要
- 页内审批动作：交付 push / 暂不交付 / 放弃在页内完成；继续 / 重试切回对应会话后于 chat 执行
- 点击列表项回 chat 并锚定对应任务卡

**红线对齐**
- **[PRIVACY]**：用户任务全端侧执行，无新增网络面
- **[I18N]**：静态文案不入库——标题按任务类型、错误按 errorCode 取 string resource，五语同步；displayName 为体系自带名原样展示

## 5. IM 远程控制（❄️ 冻结 · 低优先实验线）

> **状态口径（与 PRODUCT.md §6.6 统一）**：❄️ 冻结（2026-07）· 低优先实验线——2026-07-27 曾重新激活为低优先级实验线。代码保留不删，不占用核心产品研发资源，仅在相册/编辑/对话主路径稳定后按需评估投入，并设定明确的数据决策点。

### 5.1 产品定位

IM 远程控制是 PoLang 的**实验性融合入口**，将智能相册的核心能力（浏览、编辑、搜索、管理）通过 IM 机器人暴露为远程可调用服务。用户无需打开 App，只需在飞书等 IM 中发送消息，即可完成照片处理、相册管理等操作。

**设计原则**：
- **场景互补**：IM 适合「即发即走」的轻量操作，App 内提供完整编辑体验
- **结果交付**：编辑后的图片直接通过 IM 返回，无需跳转 App
- **隐私分级**：敏感操作（人脸编辑等）需设备端确认，非敏感操作（裁剪/调色）直接执行
- **异步解耦**：大文件处理后台执行，完成后通过 IM 通知
- **数据决策**：设定人均每周使用次数等核心指标，不达标则冻结该线

### 5.2 飞书机器人接入

**配置方式**
- 用户通过飞书应用目录搜索「PoLang 相册助手」添加机器人
- 或通过自建应用配置 App ID 和 App Secret
- 设备绑定：在 App 中获取配对码，在飞书中发送完成绑定
- 支持多设备绑定（手机 A + 平板 B），可通过 IM 指定目标设备

**交互流程**
![飞书远程控制闭环](assets/diagrams/im-feishu-architecture.png)

> **架构简化**：设备端直接通过飞书 OAPI SDK 建立 WebSocket 长连接，**无需任何云端中转服务**（无 SCF/Cloudflare Workers）。消息接收走飞书 WS 推送，消息回复走飞书 OAPI HTTP。

**消息类型支持**
| IM 消息类型 | PoLang 处理 |
|-------------|-----------|
| 文本消息 | LLM 解析意图 → 生成命令 → 设备执行 |
| 图片消息 | 接收图片 → 设备端编辑/分析 → 返回结果 |
| 富文本卡片 | 展示处理进度、对比结果、操作确认 |
| 交互式卡片 | 参数选择、确认/取消按钮、滑块调节 |

### 5.3 远程命令能力

**相册操作**
| 命令 | IM 示例 | 说明 |
|------|---------|------|
| 浏览相册 | 「最近拍的照片」 | 返回最近照片缩略图列表（卡片形式） |
| 搜索照片 | 「找出去年夏天的照片」 | 自然语言搜索，返回匹配结果 |
| 查看详情 | 「这张照片的拍摄信息」 | 返回 EXIF + AI 标签 |
| 删除照片 | 「删除这张模糊的照片」 | 需确认 → 设备端执行 |
| 创建相册 | 「建个叫'旅行'的相册」 | 设备端创建命名相册 |
| 移动照片 | 「把这张移到旅游相册」 | 跨相册移动 |

**图片编辑**
| 命令 | IM 示例 | 说明 |
|------|---------|------|
| AI 优化 | 「帮我优化这张照片」 | 自动识别场景 + 推荐参数 |
| 美颜调节 | 「磨皮 50，美白 30」 | 远程调节 + 返回处理后图片 |
| 滤镜切换 | 「调成复古风格」 | 滤镜预设应用 + 返回预览 |
| 智能消除 | 「把照片里的路人去掉」 | 需指定区域或 AI 自动识别 |
| 裁剪调色 | 「裁剪成 1:1，再调亮一点」 | 组合命令远程执行 |
| 批量处理 | 「把上周的照片都调成冷色调」 | 批量处理 + 打包返回 |

**照片发送回 IM**
- 编辑后的图片自动通过 IM 返回
- 支持原图/压缩图选择（文件大小超过 20MB 自动压缩）
- 多图结果以卡片轮播形式展示
- 支持「再调整」交互：用户不满意可继续发消息微调

### 5.4 远程图片接收与处理

**图片上传流程**
1. 用户在飞书发送图片 → 飞书开放平台接收
2. FeishuChannelHandler 收到事件 → RemoteCommandDispatcher 解析意图
3. 设备端下载图片（经飞书资源 API）→ 执行编辑命令
4. 结果图片直接通过飞书 OAPI 上传并回复到对话

**图片处理限制**
- 单张图片最大 20MB（超限自动压缩）
- 同时处理队列上限 5 张（防止设备过载）
- 处理超时 60s（超时返回错误提示）
- 隐私保护：图片不经任何第三方服务器中转

### 5.5 多设备管理

- 同一飞书账号可绑定多台设备（手机/平板）
- 发送消息时默认选择「最近活跃设备」
- 支持@指定设备（如「@我的平板 处理这张照片」）
- 设备状态：在线/离线/处理中，通过 IM 卡片展示
- 设备解绑：IM 中操作或 App 设置页

### 5.6 IM 远程控制体验红线

| 红线 | 定义 | 验证方式 |
|------|------|----------|
| **命令响应** | IM 消息发出到 Bot 回复 < 3s（含 LLM 推理 + 设备执行） | 端到端计时 |
| **图片处理** | 单张编辑 < 5s（1080p 照片） | 计时 |
| **图片回传** | 处理完成到 IM 可见 < 2s | 计时 |
| **鉴权失败** | 非法请求拒绝 < 500ms | 压测 |

### 5.7 隐私与安全

- **端侧推理优先**：人脸检测/美颜处理优先设备端执行，飞书仅做消息通道
- **传输加密**：设备 ↔ 飞书全程 HTTPS + 飞书平台标准鉴权
- **数据不留存**：图片不经任何第三方服务器中转
- **操作审计**：所有远程命令操作记录本地日志，用户可查看
- **设备授权**：首次绑定需 App 内配对码确认，支持远程解绑

### 5.8 远程命令意图分类

| 意图类别 | 示例指令 | Agent 响应 | 执行位置 |
|----------|----------|------------|----------|
| **远程浏览** | 「最近有什么照片」 | 照片列表卡片 | 端侧检索 → 飞书回复 |
| **远程编辑（简单）** | 「调成黑白」 | 处理后的图片 | 端侧 GPU → 飞书回复 |
| **远程编辑（复杂）** | 「把路人P掉」「磨皮美白」 | 处理后的图片 + 说明 | 端侧 AI → 飞书回复 |
| **远程管理** | 「删掉模糊的照片」 | 确认 → 执行 → 结果 | 端侧执行 → 飞书回复 |
| **远程搜索** | 「找出去年夏天的照片」 | 搜索结果卡片 | 端侧检索 → 飞书回复 |
| **设备查询** | 「设备状态」「还剩多少空间」 | 状态信息卡片 | 端侧查询 → 飞书回复 |

配色 SSOT 为 `design-tokens.json`（v2.2.3，2026-09-13），经 `gen-design-tokens.py` 生成双端镜像（详见 `docs/03-TECHNICAL-SPECS/DESIGN_TOKENS_SPEC.md`）。

| 用途 | 色值 | 说明 |
|------|------|------|
| Light Primary | #0E9F6E | 薄荷绿主色，强调操作 |
| Light Surface | #F1FAF5 | 浅色模式底色（薄荷白） |
| Dark Primary | #2FE385 | 深色模式主色（亮薄荷绿） |
| Dark Surface | #071510 | 深色模式底色（近黑绿） |

### 6.3 摄影美学

- 真实自然：避免过度美颜，保持肤色自然
- 高级质感：参考徕卡色彩科学
- 情感表达：通过滤镜传达情绪

- 字符串资源 ID：`[feature]_[description]` 小驼峰

| 指标 | 目标 | 验证方式 |
|------|------|----------|
